Resumeira

Local-first meeting notes. It records the room and the call, transcribes them, and writes the note. No bot joins your meeting.

Pre-alpha · not yet dogfooded · AGPL-3.0

What it does

Resumeira records two tracks at once — your microphone and whatever your computer is playing — transcribes them, and turns the transcript into a Markdown note with a summary, the decisions taken, and action items with owners. Because it captures the machine's own audio rather than joining the call, it works the same for a hybrid meeting, a Teams call, and two people at a table.

No bot in the call

Nothing appears in the participant list, and nobody has to approve a recorder. It captures the audio your machine already has.

Transcription can be offline

A downloaded Whisper model transcribes on your CPU, or you point it at Groq/OpenAI with your own key. You choose which — there is no fallback in either direction.

Your files

Notes are Markdown in a folder you pick. Open them in Obsidian, grep them, back them up by copying the folder. The database is only a search index and can be rebuilt.

No account, no telemetry

Nothing to sign up for, and no analytics. API keys live in the OS keychain and never cross into the app's web view.

How a meeting becomes a note

  • Record: microphone and system audio as two separate Opus tracks, written incrementally so a crash costs seconds, not the meeting.
  • Transcribe: local Whisper, or Groq/OpenAI with your key — the route is resolved before recording starts, so you never discover at the end that it could not run.
  • Summarize: your own LLM key, or an agent CLI already installed on your machine (claude, codex, gemini).
  • Write: one Markdown note per meeting, plus a SQLite index for search that is rebuildable from the notes themselves.

What it does not do yet

Nobody has used it for a real meeting yet. The whole path is wired and covered by tests, but no note produced by the full pipeline has been read by a person — so treat any claim about note quality as untested. There is also no live transcription while you record, and no local summarization: summarizing sends the transcript to the LLM provider you configured, with your key. If that is not acceptable to you, this app cannot write your notes today.

Privacy, concretely

Audio and transcripts leave the machine only through a route you configured yourself, and never as a fallback: a missing local model is an error you see, not a silent upload. There is no telemetry. Transcripts, audio and API keys are never written to the log.

Windows

Installer (.exe)  ·  MSI
64-bit, installs to Program Files. The most tested of the three.

Windows, portable

Executable (.exe)
No installer: download it, run it, delete it. Needs the WebView2 runtime, which Windows 11 and up-to-date Windows 10 already have.

macOS

Disk image (.dmg)
Apple Silicon, macOS 13 or later. Asks for Screen Recording — see below.

Linux

AppImage  ·  Debian package (.deb)
x86-64. Needs PulseAudio or PipeWire — see below.

All three builds capture system audio, by a different route each: Windows through WASAPI loopback, macOS through ScreenCaptureKit, Linux through the default output's PulseAudio monitor (PipeWire serves this too). Two things follow. On macOS the app asks for Screen Recording permission, because that is the only supported way to record system audio — the app registers no video handler and never receives, stores or sends an image of your screen. On Linux you need PulseAudio or PipeWire; a machine running bare ALSA has no monitor to record. Windows is still the only one of the three with a recorded meeting behind it — the other two are built and tested on every commit, not yet used in anger.

These builds are unsigned, because code-signing certificates cost money this project does not take. Windows SmartScreen will call the publisher unknown — “More info”, then “Run anyway”. macOS will refuse the first launch; allow it in System Settings → Privacy & Security. Building from source avoids both.

Or build it

The audio stack compiles libopus and whisper.cpp from source, so a build needs Node 22, Rust, CMake and a C/C++ toolchain (on Windows, the MSVC “Desktop development with C++” workload): 

git clone https://github.com/leoddias/resumeira.git
cd resumeira
npm install
npm run tauri dev
